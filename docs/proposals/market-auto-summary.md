# 提案：雲端轉錄成功後自動產生摘要（可選，預設關）

## 市場參考
Otter、Plaud、Notta、Fireflies 等 AI 錄音／會議工具在轉錄完成後會直接給出摘要，使用者不必再按一次。RecorderApp 目前需要在逐字稿完成後手動按「產生摘要」。

## 不重複確認
- 現有：手動摘要（#4/#33 格式＋手動重新整理）、自動雲端轉錄（`autoAfterRecording`）、完成通知（#77）。
- 沒有任何 PR 會在轉錄完成後自動送出摘要。

## 行為
1. 雲端設定新增開關「雲端轉錄成功後自動產生摘要」，**預設關閉**；舊設定 JSON 一律視為關閉。
2. 開啟時跳確認對話框，寫明：**每次雲端轉錄成功後會再送出 1 次摘要請求（只送逐字稿文字，不上傳音訊），會使用摘要模型並可能產生 API 費用。**
3. 觸發條件（全部成立才送）：
   - 雲端轉錄 worker 本次結果為 `SUCCESS`（部分完成、失敗、取消都不送）。
   - 逐字稿文字非空白。
   - 這份逐字稿（同一個 transcript id）還沒有任何非取消狀態的摘要（避免續傳／重跑時重複收費）。
   - 目前設定與 API Key 仍有效（`validate` 通過）。
4. 使用現有 `startSummary(recordingId, transcriptId)`，格式用已儲存的預設格式；不會覆寫既有摘要。
5. 失敗只記 log，不影響轉錄結果；不自動重試摘要（摘要 worker 自己的既有重試規則不變）。
6. 手動與自動觸發的轉錄都適用（設定文字寫明）。

## 不做
- 不改資料庫；不新增任何其他雲端呼叫；不自動送到外部服務。
- 本機（離線）轉錄不觸發。

## 測試
- 純函式 `AutoSummaryPolicy.shouldStart(...)`：開關關／非 SUCCESS／空白文字／已有摘要 → 不送；已有摘要但為取消 → 可送。
- 舊設定 JSON 預設關閉。
