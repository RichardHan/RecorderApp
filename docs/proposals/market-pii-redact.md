# 提案：送出雲端摘要前遮蔽個資（本機，可選，預設關）

## 市場參考
Otter、Fireflies、Notta 的企業方案提供 PII redaction（電話、Email、證號、卡號遮蔽）。RecorderApp 的摘要與章節功能會把逐字稿**文字**送到使用者設定的雲端模型，目前沒有遮蔽選項。

## 不重複確認
現有與所有提案／實作 PR（#3–#80）都沒有個資遮蔽。

## 行為
1. 雲端設定新增開關「送出摘要／章節前遮蔽電話、Email、身分證號、卡號」，**預設關閉**；舊設定 JSON 視為關閉。
2. 開啟後，在本機把要送出的文字替換為代號再送出：
   - Email → `[Email]`
   - 台灣手機（09xx-xxx-xxx，可含空白／連字號、或 +886 9…）與帶區碼的市話（如 02-2345-6789、(02)23456789）→ `[電話]`
   - 台灣身分證／居留證號格式（1 個英文字母＋1/2/8/9＋8 位數字）→ `[證號]`
   - 13–19 位數字（可含空白／連字號）且通過 Luhn 檢查 → `[卡號]`
3. 套用範圍：背景雲端摘要（`CloudSummaryWorker`）與手動產生章節。**原始逐字稿與本機資料完全不改**。
4. 不適用：雲端**音訊**轉錄（音訊無法在本機遮蔽，設定文字會寫明）、即時（live）重點（另一組設定，之後再議）。
5. 摘要結果中可能出現代號，這是預期行為。
6. 遮蔽是盡力而為的格式比對，設定文字寫明「無法保證找出所有個資」。

## 不做
- 不改資料庫，不新增雲端呼叫。
- 不遮蔽人名（容易誤判，跳過）。

## 測試
純函式 `PiiRedactor.redact(text)`：各類型命中、Luhn 不通過的數字不遮、一般數字／時間（如 00:12:30、2026-11-15、金額 500000）不誤遮；設定預設關。
