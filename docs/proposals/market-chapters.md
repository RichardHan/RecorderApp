# 提案：段落章節（依主題分段的目錄＋真實時間跳轉）

> 狀態：**尚未實作，等待使用者選 agent 開工。** 這個 PR 只有規格文件，沒有程式碼、設定或 workflow 變更。
> 基準：`feature/drive-auto-upload` @ c190555。來源存取日期：2026-11-09（台北時間）。
## 參考來源
- tl;dv「AI Meeting Notes」：https://intercom.help/tldv/en/articles/7198123-ai-meeting-notes ：Smart Topics 會在會議中自動標時間、摘要重點時刻，依主題分組，每則筆記連到錄影的該時間點。
- Read AI「API Reference」：https://support.read.ai/hc/en-us/articles/49381161088659-API-Reference ：會議資料可展開 `chapter_summaries`、`topics` 等欄位，顯示這是正式產品功能。

**來源產品的功能** = 自動主題分段加時間連結。**我們的版本** = 錄音結束後，**由使用者手動觸發**一次雲端分段，只能引用逐字稿裡已有的真實分句時間；播放頁顯示章節目錄，點選就跳轉。

## 和既有 PR 的差別
- PR3（重點條目附來源時間）：替**每條重點**附上引用。本提案則是替**整段錄音**建立導覽目錄，不改重點內容。
- PR4（摘要格式）、PR7（問答）：不重疊。
- PR1、#23（搜尋）：搜尋是找關鍵字；章節是瀏覽結構。

## 最小範圍
- 前提：逐字稿已有真實分句時間（依賴 #21 或等效資料）。沒有時間資料時，按鈕停用並顯示原因。
- 播放頁「章節」分頁：「產生章節」按鈕 → 確認對話框（說明會把逐字稿送到目前設定的雲端服務，並使用 token）→ 產生 3–12 個章節，每個章節有標題（≤ 20 字）和開始時間。
- 模型輸入：逐字稿各句加上**句子編號**（不是時間）。模型只能回傳 `[{title, start_sentence_index}]`；App 再用本機時間表把編號換成時間。**模型無法捏造時間。**索引越界或沒有遞增時，整批丟棄，不採用。
- 可以取消；取消或失敗時不保存部分結果。可以手動改標題或刪除章節。

## 資料模型（Room，需遷移）
- `recording_chapters`：`id`、`recording_id`（FK CASCADE）、`title`、`start_ms`、`source_sentence_index`、`created_at`、`transcript_revision`。
- 若逐字稿之後被重新轉錄（revision 改變），章節標示「可能已過期」，不自動重算。

## API／成本／隱私
- 沿用現有雲端設定與金鑰。每次產生大約多送一次完整逐字稿的 token，**有成本**。預設不自動執行，只在使用者手動觸發時呼叫。
- 長錄音：超過模型上下文時，分塊送出再合併（第一版可以直接拒絕超過上限的錄音，並顯示上限）。
- 不記錄逐字稿或回應內容到 log。

## 低資源／離線
離線時不能產生章節，已保存的章節照常顯示與跳轉。不做本機 LLM（手機資源不足，非本 PR 範圍）。

## 驗收測試
1. 單元：回應解析與驗證（越界、非遞增、空陣列、標題過長）。
2. 單元：句子編號對時間的對照正確；沒有時間資料時拒絕產生。
3. 單元：取消時不寫入資料庫。
4. Room 遷移測試；刪除錄音時章節一起刪除。
5. 手動：點章節後播放位置等於該句的開始時間（誤差在一句之內）。
