# 提案：會後跟催草稿（先預覽，確認前不送出）

> 狀態：**規格提案，尚未實作，等待使用者選擇 agent；勿合併視為功能完成。**
> 這個 PR 只有規格文件，沒有程式碼、設定或 workflow 變更。
> 基準：`main` @ 3903947。來源存取日期：2026-11-14（台北時間）。

這是獨立改編：用**已接受的摘要／待辦／使用者筆記**產生一封可編輯的跟催訊息，預設只複製或透過系統分享面板送出。沒有使用者明確確認，App **不得**把這則草稿發到任何外部服務。

## 參考來源（公開官方說明）

### Granola Chat Workflows
- Workflows in Granola Chat：https://docs.granola.ai/help-center/getting-more-from-your-notes/workflows-in-chat （本頁於 2026-11-14（台北時間） 開啟）
  - Chat 可協助會後工作，例如草擬並寄出跟催信件、草擬並送出 Slack 訊息、找時間並建立 Google 日曆行程。
  - **Granola 會先準備可編輯草稿，供使用者審查。「在你於 Chat 確認之前，什麼都不會送出，也不會加進日曆。」**
  - 目前這些動作在 Granola 桌面版，且需使用者自行連線 Gmail／Slack／Google Calendar。

**我們的改編（相對 Granola）**：只做「跟催訊息草稿＋使用者編輯＋複製或系統分享」。不連 Gmail、不建立日曆行程、不自動加入會議。若未來 #46 Slack 同步已實作且使用者已單獨同意，可在確認後把**這一則使用者編好的草稿**送到已設定的頻道；這仍是一次性、需再按確認，不是另開連續同步。未實作或未開啟 Slack 時，不得出現「送到 Slack」為預設動作。

### Granola Recipes（只說明「可重複提示」背景，本提案不做食譜系統）
- Recipes：https://docs.granola.ai/help-center/getting-more-from-your-notes/recipes （本頁於 2026-11-14（台北時間） 開啟）
  - Recipes 是可重複使用的提示模板，例如會後寫跟催信。這與本 App 已有的摘要格式／清理提案不同。本提案 v1 用一支固定、使用者可在設定改寫的跟催提示，不做完整 recipe 市集。

## 與 RecorderApp 現況的關係
- 已有：摘要（預設精簡）、即時重點、#30 文字匯出、#34 待辦（若已合併）、雲端轉錄同意與 `EncryptedKeyStore`。
- #41 清理是整理逐字稿本身；#7／既有問答是對錄音提問。本功能產出的是**要寄給別人的跟催文案**，不是另一份內部摘要。
- #46 Slack 連續同步（若尚未合併）不是本功能的前置條件。

## 使用者問題
會議結束後，要把結論與待辦寫成一則給同事的短訊或信件，現在只能自己從摘要複製再改寫，容易漏項或寫得太長。

## 最小範圍（v1）
- 播放頁（錄音已結束、且至少有「已接受的摘要」或已存在的待辦／使用者筆記之一）提供「產生跟催草稿」。
- 若完全沒有這些材料：拒絕產生並提示先產生或接受摘要，**不拿未經接受的即時草稿去寫信**。
- 送進模型的內容僅限：已接受摘要、已存在待辦（含負責者與期限——只在使用者或先前流程已寫明時）、已存在決議（若該功能已上線）、使用者自己寫的筆記。可附「句 ID 列表」供模型引用，但輸出不得發明新的時間或發言者。
- 輸出：一則短跟催草稿（預設繁體中文；若摘要明顯是其他語言，跟隨摘要語言，可在對話框改）。結構建議：問候／場合一句、結論幾點、待辦（有就列、沒有就省略該段）、收尾。語氣中性、簡潔。
- 預設提示存在設定中，可編輯；空提示則用內建預設。不得把錄音音訊送出，只送上述文字。
- 使用者可在結果框**完整編輯**後：
  - 「複製」（預設主按鈕）；
  - 「用系統分享」；
  - 僅當 Slack webhook／token 已設定且該同步功能已開啟時，才顯示「確認後送到 Slack」。按下去才送這一則，並顯示成功或失敗。沒有連線時不顯示此按鈕。
- 關掉對話框可選擇「保留這份草稿在本機」或丟棄。每則錄音最多保留一份最新草稿（再產生會請確認是否覆蓋未分享的舊稿）。

## UI
- 入口在摘要／匯出附近，文案避免「已寄出」除非真的送出。
- 第一次使用雲端產生時，走既有雲端同意（或同等同意頁）：說明會把摘要與待辦文字送到使用者已設定的雲端模型，不會送音訊，不會自動寄信或排程。
- 產生中可取消。失敗顯示可理解錯誤，不露 API 金鑰。
- 若模型輸出空、或只寫「目前無重點」這類無內容句：視為失敗，不覆蓋舊草稿。

## 資料模型
- 本機欄位建議：`audioId`、`draftText`、`updatedAt`、`sourceSummaryHash`（或版本標記，避免誤用過期摘要而不自知；若摘要已更新，開啟時提示「摘要已更新，要不要重產生？」）。
- 草稿只存本機。不進雲端帳號、不預設外送。
- 無破壞性遷移。

## API／成本／隱私
- 使用既有雲端設定：總開關預設 OFF，未同意不得呼叫。
- 只送文字材料，長度需截斷到模型輸入上限並在 UI 註明「已截斷較長逐字稿，未整份送出」——v1 **預設不送逐字稿全文**，避免成本與隱私擴大；設定可選「附上摘錄」，預設關。
- 成本：一次產生一次呼叫。取消中的請求不得再寫入草稿。
- 禁止把 webhook URL、API 金鑰寫進提示或 log。

## 取消、競態、離線
- 同一錄音同時只允許一個產生工作；新的請求取消舊的或拒絕重入（擇一，需在實作註明）。
- 完全離線或無金鑰：禁用按鈕並說明原因。
- 低資源：草稿產生是短請求，失敗要可重試。

## 驗收測試
- 無已接受摘要且無待辦／筆記：按鈕提示阻擋，不發 API。
- 有摘要：產生後畫面可編輯；未按複製／分享／確認外送前，無任何網路 POST 到 Slack 或其他整合。
- 使用者改了幾個字再複製：剪貼簿內容為改後文字。
- 取消產生：不寫入或覆蓋草稿。
- 空輸出或「目前無重點」：保留舊草稿，顯示失敗。
- 雲端關閉：無法產生。
- Slack 未設定：沒有「送到 Slack」按鈕。
- 模型輸出若含未出現在來源中的負責人／日期：驗收應要求提示詞與後處理指示「不得發明負責人、期限或未出現的事實；沒寫就省略」。此項以單元測試鎖定提示與（若有）校驗規則，不保證模型永不幻覺，但 UI 需有「請核對後再送出」提示。

## 依賴
- 既有雲端同意、摘要接受流程、加密金鑰存放。待辦／決議為可選增強。
- Slack 按鈕依賴未來或並行的 #46，但本功能在沒有它時仍完整（複製／系統分享）。

## 非目標
- 自動寄信、自動建日曆、自動建任務票（Linear／Jira 等）。
- 完整 Granola Recipe 市集或跨多場會議工作流。
- 會議中途的「到目前為止我錯過什麼」（與即時重點重疊）。
- 未確認就外送；為了跟催去開啟新的第三方整合（除既有、已同意的 Slack）。
