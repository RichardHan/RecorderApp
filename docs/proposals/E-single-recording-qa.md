# 提案 E：對單段錄音提問，回答附來源時間（只有手動提問才會送出）

## 參考依據
- **Notion 官方文件**：
  - 可以問 Notion AI／Agent 過去會議的事，回答會附上原始討論的連結（https://www.notion.com/help/guides/get-the-most-out-of-your-business-trial-with-notion-ai ，「Ask your Agent about past meetings」）。
  - 會議中、會後也有「Catch me up」、「Recap decisions」這類可一鍵執行的 skills（https://www.notion.com/help/ai-meeting-notes ，「Run skills on your meeting notes」段；官方註明 **skills 在 mobile app 上不提供**）。
- **我們的做法**：只針對單段錄音提問、使用者必須手動按下才會送出、回答附上來源片段。

## 使用者好處
不用重聽整段錄音，就能問「Amy 說報價什麼時候交？」，並直接跳到原話。

## 範圍（最小可行）
1. 「雲端轉錄」對話框（或之後的摘要區）加一個「問這段錄音」輸入框和「送出」按鈕。
   - **不會自動送出**，也沒有自動建議問題。
2. 第一次使用時跳出確認視窗：說明會把哪份逐字稿送到哪個服務、可能計費。
3. prompt 包含：
   - 帶編號的片段（引用格式和驗證方式跟提案 A 相同）。
   - 規則：只能根據逐字稿回答；**找不到就明確回「逐字稿中找不到」**，不推測、不編造。
4. 長度限制：逐字稿超過上限時會被截斷，**而且回答要明確顯示「只用了前／後 X 分鐘」**，不能讓使用者以為用了全文。
5. 問答紀錄另外存在 `recordings/<id>/qa/*.json`，可以刪除，不修改原有的資料。

## 相依性
- 建議在 A 之後做，共用引用的解析與驗證；也需要 A 規劃的摘要或對話框入口。
- 不依賴 PR #1、#2。

## 資料、隱私與費用
- 每問一題就是一次付費呼叫，會送出整份（或截斷後的）逐字稿，token 用量取決於逐字稿長度。
- 使用摘要服務的 Endpoint、Key、模型設定。使用者沒設定時，按鈕不能按，並說明原因。

## 邊界情況
- 逐字稿是空的或全部失敗：不能提問。
- 模型回傳無法驗證的引用：回答照樣顯示，但標示「未能驗證來源」。
- 網路或 API 錯誤：顯示錯誤來源，不自動重試。

## 不在範圍內
- 不做跨多段錄音的問答。
- 不做會中即時問答。
- 不做 Agent 動作（建立任務、寄信等）。

## 驗收測試
- 沒有按下「送出」，就不會有任何網路請求（用假的客戶端驗證）。
- 截斷時，回答區會顯示用了哪個範圍。
- 模型回「找不到」時，照原樣顯示。
- 引用驗證沿用 A 的測試。

## 共通約束（所有提案都要遵守）
- **目前只是規格，還沒實作**。合併這份文件不代表功能已完成。
- 預設的重點整理 prompt 維持精簡；沒有重點時只回「目前無重點」，不強迫列出分類或待辦。
- 雲端功能預設關閉。API Key 一律由使用者明確選擇（轉錄 Key 與摘要 Key 分開）；任何把資料送到雲端的動作，都要先有使用者同意或手動確認。
- 時間戳只能來自真實的雲端分段（`SegmentResult.startMs/endMs`），不推測時間，也不編造說話者。
- 每段錄音的資料彼此隔離（參考 v1.7.14 的修正），不會互相影響。
- 原始逐字稿和摘要（`TranscriptRecord`/`SummaryRecord`）視為不可修改；任何修訂都另存成新的一筆，不覆蓋舊的。
