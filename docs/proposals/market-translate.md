  - 文件註明翻譯會消耗配額；準確度依賴逐字稿品質；譯文本身不可編輯（要改請改原文再重翻）。

**來源產品的功能** = 會後翻譯＋三種檢視；另有即時雙語（我們不做）。  
**我們的版本** = 使用者手動對**已保存的逐字稿**觸發一次翻譯，結果存在本機，播放頁可切換單語／雙語對照。沿用使用者已設定的雲端 endpoint／金鑰。

## 與既有提案的差別
- 轉錄提示已要求「原文語言 verbatim」；本提案是**另外一層譯文**，不改原始逐字稿。
- #26 詞彙表：改善辨識拼寫，不是翻譯。
- #30 匯出文字／#27 匯出提案：可之後把譯文列入匯出選項，但本 PR 不做匯出。
- PR7 問答：問答不是全文翻譯。

## 使用者問題
錄音常中英夾雜或整段外語；自己複製到別的翻譯工具很麻煩，也容易漏掉時間對齊。

## 最小範圍
- 播放頁逐字稿工具列：「翻譯」→ 選目標語言（第一版固定清單：`zh-Hant`、`en`、`ja`，可再擴）→ 確認成本與上傳範圍 → 送出。
- 檢視模式：原文｜譯文｜雙語（逐句或逐段並排）。雙語列必須對齊**同一個 segment id／句子編號**；不能用字數比例硬切。
- 譯文**不可直接當權威編輯**；若要修正，改原文逐字稿（若未來有編輯能力）或刪譯文後重翻。第一版譯文唯讀即可（與 Notta 文件一致）。
- 模型契約：輸入為編號句子列表；輸出 `[{id, translation}]`，id 必須對得上。缺漏／多餘 id → 整批失敗，不採用。**禁止發明原文沒有的句子。**

## 資料模型
- 本機檔或 Room：`transcript_translations`（`recording_id`、`target_lang`、`payload_json`、`source_revision`、`created_at`）。同一錄音同一語言只保留最新一份。
- 原始逐字稿 revision 變了：標「原文已更新，譯文可能過期」，不自動重翻。

## API／成本／隱私
- 沿用現有雲端設定；翻譯是**另一次**文字請求（通常比重新轉錄便宜，但仍**有 token／額度成本**，不可宣稱免費）。
- 確認對話框必須寫：會把逐字稿文字送到你設定的服務；音訊檔不會因翻譯再傳一次。
- 雲端總開關仍為 opt-in；未開啟雲端／無金鑰時按鈕停用並說明原因。

## 邊界情況
- 空逐字稿、轉錄未完成：停用。
- 超長逐字稿：按句子分塊翻譯再合併；任一塊失敗則整次失敗並可重試失敗塊（實作可先整次失敗）。
- 離線：不能新翻；已存譯文可離線閱讀。
- 目標語言若與原文「看起來相同」：仍允許（使用者可能要正規化），但 UI 提示可能無明顯差異。

## 驗收測試
1. 單元：輸出 id 對齊／缺漏拒絕／禁止額外句子。
2. 單元：三種檢視只讀正確欄位；切換不改存檔。
3. 單元：revision 過期標記。
4. 手動：確認對話取消則不發請求；成功後雙語列與播放跳轉仍用**原文**時間。

## 依賴
需要已保存、可分段的逐字稿（雲端或離線皆可）。時間跳轉用原文時間（#21）。

## 非目標
錄音中即時雙語、40+ 語言一次做完、離線本機 NMT 模型、改寫風格、自動偵測語言後偷偷翻、把譯文覆寫進原始逐字稿。
