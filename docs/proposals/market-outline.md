## 參考來源（公開官方說明）
- Plaud「Mind Map」：https://support.plaud.ai/hc/en-us/articles/51900651473177-Mind-Map （June 05, 2026 Updated；本頁於 2026-11-09（America/Chicago 時區） 開啟）
  - Mind Map 由錄音的 summary 產生階層結構（主題／子主題／要點），方便掃讀長對話。
  - 出現在 notes 的 summary 後面；要改內容需重新產生 transcript／summary；Web 與 App 同步。

**來源產品的功能** = 圖形化 mind map。  
**我們的版本** = **可摺疊的文字階層大綱**（Android 上較務實），掛在重點摘要下方。第一版優先用**本機規則**把現有「- 」摘要收成一層或兩層；只有使用者手動點「AI 整理大綱」時才額外打雲端（opt-in）。

## 與既有提案的差別
- 預設精簡摘要（`LiveCloudSettings.DEFAULT_SUMMARY_PROMPT`）維持條列、不湊數。大綱是**另一種檢視**，不取代預設摘要。
- PR4／#33 可選摘要格式：改的是摘要生成格式。本提案是對**已有摘要文字**做結構化檢視。
- #29／#35 章節：章節依時間軸切錄音；大綱依主題層級組織摘要文字，不必有時間。
- PR3 引用：大綱節點若之後要附來源，可另開；本 PR 不要求。

## 使用者問題
摘要超過十來點時，平面條列不好掃；使用者想先看「主題 → 要點」再展開。

## 最小範圍
### A. 本機大綱（預設，零成本）
- 解析現有摘要：`-` 開頭行為葉節點；若某行以「主題：」或 Markdown `##` 出現（未來格式），當成父節點。
- 若全是平鋪條列：顯示為單一「重點」根節點下的葉子（仍可全部摺疊／展開）。
- UI：`LazyColumn`＋展開箭頭，不要做複雜畫布手勢。

### B. 可選 AI 整理（手動）
- 按鈕「整理成大綱」→ 確認成本 → 送目前摘要（不是整份逐字稿，降低成本）→ 回傳 `[{title, children:[...]}]`，最多 2 層、總節點 ≤ 20。
- 失敗或取消：保留本機大綱。成功後可「回復本機大綱」。

## 資料模型
- 可只存「AI 大綱」JSON 於錄音中繼或小表 `recording_outline`（`recording_id`、`mode`=`local|ai`、`json`、`summary_hash`、`updated_at`）。
- `summary_hash` 不符時標過期；本機模式可即時重算，不必遷移也能先做（衍生檢視）。

## API／成本／隱私
- A 完全本機。B 只在確認後送**摘要文字**（通常短於逐字稿）。仍有 token 成本，UI 要寫明。
- 不送音訊；不自動執行。

## 邊界情況
- 摘要為「目前無重點」或空白：顯示空態，不呼叫 AI。
- 摘要更新：本機大綱跟著變；AI 大綱標過期。
- 低資源：預設走 A；B 可取消。

## 驗收測試
1. 單元：平鋪條列 → 單根＋葉子；含 `##`／「主題：」→ 兩層。
2. 單元：AI JSON 驗證（超過 2 層、節點過多、空 title → 拒絕）。
3. 單元：取消不覆寫已存 AI 大綱。
4. UI：展開／摺疊狀態在旋轉後可接受重置（不強制持久化）。

## 依賴
需要已有重點摘要字串。不依賴章節或待辦。

## 非目標
圖形化 mind map 畫布、自動每次摘要後打雲端、多層無限樹、匯出圖片、協同編輯。
