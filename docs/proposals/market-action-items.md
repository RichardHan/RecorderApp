# 提案：待辦清單可勾選（只取摘要中明確說出的待辦，使用者確認）

> 狀態：**尚未實作，等待使用者選 agent 開工。** 這個 PR 只有規格文件，沒有程式碼、設定或 workflow 變更。
> 基準：`feature/drive-auto-upload` @ c190555。來源存取日期：2026-11-09（台北時間）。
## 參考來源
- Fathom「Navigating the Settings Page」：https://help.fathom.video/en/articles/3239617 ：開啟「Auto-Generate Action Items」後，會把會議中提到的待辦放到通話頁的 Action Items 區。
- Fathom「Advanced AI Features」：https://help.fathom.video/en/articles/640768 ：偵測待辦（含指派對象），並用待辦產生追蹤信草稿。
- Otter「Export conversations」FAQ：https://help.otter.ai/hc/en-us/articles/360047733634-Export-conversations ：Action Items 無法直接匯出，只能手動複製。

**來源產品的功能** = AI 偵測待辦、指派人，並串接外部工具。**我們的版本** = 只把**現有重點摘要裡已列出的待辦句**轉成本機勾選清單。**不推測負責人或期限，不建立外部任務，不寄信。**

## 使用者問題
重點摘要裡的「待辦」只是文字，會後沒辦法標記完成，也無法一次複製未完成的項目。

## 最小範圍
- 錄音詳情的「重點」區塊下方新增「待辦」小卡，預設收合。
- 來源：使用者手動點「從重點建立待辦」，才解析現有摘要文字中的待辦句。**不額外呼叫模型。**
  解析規則：摘要提示已要求「- 」條列，並且只寫明確說出的待辦；只挑使用者勾選要加入的條目（多選確認對話框），不自動全加。
- 每項：文字（可編輯）、完成勾選、建立時間。**沒有負責人或期限欄位。**若原文明確提到人名或日期，就保留在文字裡，不另外拆欄位。
- 「複製未完成」：複製為 `- [ ] 項目` 純文字。
- 使用者也可以手動新增項目。

## 資料模型（Room，需遷移）
- 新表 `recording_action_items`：`id`、`recording_id`（FK，錄音刪除時 CASCADE；移到垃圾桶時跟著隱藏，還原時恢復）、`text`、`done`、`created_at`、`source`（`summary`|`manual`）。
- 資料庫版本 +1，附遷移與遷移測試；匯出結構描述。

## 一致性與競態
- 摘要之後被重新產生：已建立的待辦**不會**自動改寫或刪除。只顯示「重點已更新，可再次從重點建立」。
- 去重：同一錄音中，文字正規化後相同的條目不重複加入。

## 隱私／成本
只在本機。不新增 API 呼叫，所以沒有額外 token 成本。

## 驗收測試
1. 單元：從固定摘要樣本解析出候選條目；「目前無重點」解析出 0 條。
2. 單元：去重、編輯、勾選狀態持久化。
3. Room 遷移測試：舊版資料庫升級後資料完整；刪除錄音時待辦跟著刪除。
4. UI 測試：沒有確認就不建立；複製未完成的格式正確。

## 依賴
無硬性依賴。可以和 PR3（重點來源時間）並存：若 PR3 先合併，待辦可以沿用該條重點的來源時間，但本 PR 不要求。

## 非目標
自動指派負責人、推測期限、提醒通知、同步到 Google Tasks／Notion／日曆、產生追蹤信。
