## 參考來源（公開官方說明）
- Google Pixel Recorder「Create, edit & manage transcriptions」：https://support.google.com/pixelphone/answer/16267698 （本頁於 2026-11-14（台北時間） 開啟）
  - 「Edit text in a transcript」：長按一個詞 → Edit word → 修改後 Save，一次改一個詞。
  - 同一頁也寫可用搜尋在錄音裡找詞句，並找到該詞被說出的時間。
- 訊飛聽見「音视频转写」說明：https://www.iflyrec.com/helpCenter_features_xftj/helpCenter_features_xftj.html （本頁於 2026-11-14（台北時間） 開啟）
  - 轉寫完成後，原文與錄音進度對照，可二次編輯；可用搜尋框檢索／取代全文。
  - 相關整理文也描述「邊聽邊改」：點文字播對應音訊，點音訊對到文字。

**來源產品的功能** = 雲端或系統內建錄音 App 裡直接改逐字稿，並與播放對齊。  
**我們的版本（獨立改編）** = 只在本機改已保存的逐字稿（雲端或離線皆可），不呼叫新 API。編輯不改音訊、不重算或捏造時間；點某句仍跳到該句**原本保存的**開始時間。

## 與既有提案／功能的差別
- #26 自訂詞彙：影響「之後」的雲端辨識提示，不修正已存稿。
- #23／PR1 搜尋、#30 匯出：讀取既有文字，不能改錯字。
- PR3 引用驗證、#37 翻譯：翻譯以原文為準；原文更新後譯文應標過期（若 #37 已實作）。
- 本 App 目前沒有逐字稿編輯路徑（查過 `origin/main` 無對應 Kotlin 實作）。

## 使用者問題
專有名詞、同音字常轉錯，使用者只能把整段複製到別處改，改完也對不回錄音時間。

## 最小範圍
- 播放頁逐字稿：長按一個詞 →「修改」→ 單行輸入 → 儲存。也可選整句修改。
- 「取代」：在本則錄音的逐字稿內搜尋並一筆一筆確認取代（不做跨錄音批次）。
- 點某句／某詞：播放頭跳到該句已保存的 `start_ms`（依賴已合併的 #21 分句時間）。沒有時間的舊稿：仍可改字，但不顯示跳轉，也**不估算時間**。
- 編輯只改文字，不剪音訊（音訊裁切已有獨立 editor 模組，本 PR 不重做）。
- 儲存後更新 `transcript_revision`（或等效版本戳），讓依賴原文的章節／譯文／決議可標過期。
- 可「還原上一次儲存」（單一 undo 即可；不必完整歷史）。

## 資料模型
- 在現有 `TranscriptStore` 上寫回修改後的句子文字；保留每個 segment 的 id 與 `start_ms`。
- 若目前結構是不可變快照：新增「使用者覆寫層」（`segment_id → edited_text`），顯示時覆寫，原始雲端／離線稿仍可對照。第一版建議覆寫層，避免破壞可重跑轉錄的原件。
- 不把編輯內容寫進 log。

## API／成本／隱私
完全本機，不新增網路請求，無 token 成本。雲端開關不受影響。

## 邊界情況
- 轉錄進行中：禁止編輯或只允許已定稿句子；未定稿句子顯示「仍在轉錄」。
- 空字串：允許刪一個詞；不允許刪到整份逐字稿只剩空白而不確認。
- 並行：若背景工作又寫入新稿，提示「原文已更新，要保留我的修改還是採用新稿」。
- 低資源：大量取代在 IO 執行緒，UI 顯示進度。

## 驗收測試
1. 單元：改一個詞不更動其他句的 `start_ms`／id。
2. 單元：沒有時間資料時允許改字、拒絕合成時間。
3. 單元：取代需逐筆確認；取消不寫入。
4. 單元：revision 遞增；undo 回到上一版。
5. 儀器／手動：點已改的詞仍跳到原開始時間（誤差在一句內）。
