# 提案：雲端用量（本機紀錄，每月統計）

## 參考依據
- **Otter 官方說明**：使用者可以在帳號設定查看本月已用與剩餘的轉錄分鐘數（Account Settings › Plan；手機在 Account）。https://help.otter.ai/hc/en-us/articles/25205539848343-When-will-my-monthly-minutes-reset
- **我們的做法**：RecorderApp 讓使用者自帶 API Key，沒有方案與額度；所以只**依手機上已存的轉錄／摘要紀錄**估算每月用了多少，幫助使用者對照自己服務商的帳單。沒有使用 Otter 的程式。

## 使用者好處
開了自動雲端轉錄後，不知道這個月大概上傳了多少分鐘、打了幾次 API。這頁讓使用者在收到帳單前就有概念。

## 範圍（最小可行）
1. 設定 › 雲端 › AI 轉錄／摘要頁面底部新增「雲端用量（本機紀錄）」區塊，預設收合，展開才計算。
2. 依「紀錄建立時間」以手機時區分月份，列出最近 6 個月：
   - 雲端轉錄次數（`TranscriptRecord.source == CLOUD`）。
   - 上傳音訊分鐘數：雲端分段中**實際送出過**（`attempts > 0`）的分段時間長度加總（切分過的段用子段）。
   - 轉錄 API 請求數：`requestCount` 加總。
   - 錄音後摘要次數（含失敗）。
3. 文字註明：只是手機上的紀錄估算，不是帳單；刪掉的錄音不會計入；章節、問答、翻譯等手動功能、即時重點未計入；費用請以服務商後台為準。

## 資料、隱私與費用
- 只讀取本機 `TranscriptStore`；不呼叫任何服務，不新增儲存，不改 Room。

## 邊界情況
- 沒有任何雲端紀錄：顯示「還沒有雲端轉錄紀錄」。
- 紀錄檔損壞：略過該檔，不影響其他。
- 很多錄音：在背景執行緒計算。

## 不在範圍內
- 不換算金額（各家價格不同且會變），不設上限、不阻擋上傳、不讀服務商帳單 API。

## 驗收測試（單元測試）
- 依本地時區分月（月底 23:30 與次月 00:30 分到不同月）。
- 只有 `attempts > 0` 的分段計入分鐘，子段取代父段。
- 離線轉錄不計入；摘要次數含失敗。
- 只列最近 6 個月，新到舊。
