# 提案：重新命名時建議標題（本機帶入摘要，或手動 AI 建議）

## 參考依據
- **Wave 官方說明**：每段錄音會自動產生簡短的描述性標題（Smart Title）；「你自己寫的標題一定優先，Wave 不會覆寫」，改設定也不會重新命名舊錄音。https://help.wave.co/ai-features/title-format-settings-choose-how-wave-names-your-recordings
- **Bower 官方說明**：轉錄後依內容產生 3–8 個字的主題式標題，且「手動設定的標題永遠不會被覆寫」。https://docs.bowerlabs.ai/capture/ai-titles
- **我們的做法**：沒有使用上述產品的程式或模型。以下依 RecorderApp 現有的重新命名對話框、`TranscriptStore` 摘要與雲端摘要設定自行規劃；**不自動改名**。

## 使用者好處
錄音檔名通常是日期時間，事後很難找。已經有摘要時，重新命名可以一鍵帶入有意義的標題，再自己修改。

## 範圍（最小可行）
1. 既有的「重新命名」對話框，在輸入框下方多兩個按鈕：
   - **從摘要帶入**（本機、免費）：取最新一份成功摘要的第一條有內容的重點，去掉「- 」與句尾標點，截到 30 字。摘要是「目前無重點」或沒有摘要時停用。
   - **AI 建議**（手動、會送出）：先跳確認視窗，說明「只會把最新摘要文字（最多 4,000 字）送到你設定的摘要服務，可能計費」，同意後才呼叫一次；不送逐字稿或音檔。
2. 兩者都**只填入輸入框**，使用者仍需按原本的「重新命名」才會改名；沿用既有改名流程（包括權限處理）。
3. AI 回覆驗證：只取第一行，去掉引號、書名號、「標題：」前綴；長度 2–40 字，不符就丟棄並提示「回應不是有效標題」。
4. 檔名不合法字元（`\ / : * ? " < > |` 與換行）一律移除。

## 資料、隱私與費用
- 「從摘要帶入」不呼叫任何服務。
- 「AI 建議」每按一次送出一次，只送摘要文字；沒有雲端設定或 API Key 時按鈕停用並說明原因。
- 不新增儲存、不改 Room。

## 邊界情況
- 摘要失敗、空白、只有「目前無重點」：兩個按鈕都不提供建議。
- 取消對話框時進行中的請求一併取消，不改任何東西。
- 永遠不會自動改名，也不會覆寫使用者正在輸入的文字以外的任何東西。

## 不在範圍內
- 不在錄音結束後自動命名。
- 不讀行事曆、不放人名。

## 驗收測試（單元測試＋人工）
- 本機建議：取第一條有內容的重點、去符號、截斷；「目前無重點」回傳空。
- AI 解析：去掉引號／書名號／前綴、只取第一行、太短太長拒絕。
- 不合法檔名字元被移除。
- Prompt 只包含摘要文字且長度有上限。
- 人工：按建議後輸入框被填入，但檔名在按「重新命名」前不變。
