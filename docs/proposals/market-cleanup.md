# 提案：語篇規整／清稿（保留逐字稿，另存一份去掉口語雜訊的書面稿）

> 狀態：**規格提案，尚未實作，等待使用者選擇 agent；勿合併視為功能完成。**
> 這個 PR 只有規格文件，沒有程式碼、設定或 workflow 變更。
> 基準：`main` @ ececf11。來源存取日期：2026-11-14（台北時間）。

## 參考來源（公開官方說明）
- 訊飛聽見「音视频转写」→「語篇規整」：https://www.iflyrec.com/helpCenter_features_xftj/helpCenter_features_xftj.html （本頁於 2026-11-14（台北時間） 開啟）
  - 適用於書面稿整理：對轉寫後文稿做規範整理，去除口語詞、語氣詞和重複內容，把冗長雜亂的語音稿整理成重點突出的書面文稿。
  - 轉寫頁可切換全部原文、全文翻譯、語篇規整等檢視（規整是原文以外的另一種檢視）。
- AudioPen FAQ：https://www.audiopen.ai/faq （本頁於 2026-11-14（台北時間） 開啟）
  - 先轉寫再說的話，再改寫成清楚、有結構的文字；仍可保留原始逐字稿。
  - 寫明「不生成不是你說的內容」；改寫程度可設 Low／Medium／High。改寫步驟在雲端並需要連線。
  - AudioPen 定位是個人思考筆記，不是會議助理。我們借用「保留原文＋可選清稿」，不做他們的寫作風格庫或跨 App 聽寫。

**來源產品的功能** = 把口語稿整理成書面稿，或依風格改寫。  
**我們的版本** = 使用者手動觸發一次「清稿」；**預設低強度**（去語氣詞、重複與明顯口誤，不重新組織成另一篇文章）。結果另存，不覆寫逐字稿，也不取代預設精簡會議重點。

## 與既有提案的差別
- 預設摘要（`DEFAULT_SUMMARY_PROMPT`）只列事實／決議／待辦，不是通順書面稿。
- PR4／#33 摘要格式：改變重點清單的格式，不是把整份口語稿寫成文章。
- #37 翻譯：語言轉換，不是去口語。
- #38 大綱：把重點摺疊成目錄。
- #36 決議、#28 待辦：抽取特定類別。
- 本提案服務「事後要貼到文件／信件的通順稿」，與會議重點並存。

## 使用者問題
逐字稿充滿「嗯、然後、我是說」和重複句，直接貼出去很難看；但使用者仍需要逐字原文來對錄音。

## 最小範圍
- 播放頁「清稿」按鈕 → 確認對話框（會把逐字稿文字送到目前雲端服務、有 token 成本；音訊不會因清稿再傳）→ 產出書面稿。
- 檢視：原文｜清稿｜對照（以**句子編號**對齊；對不上就整批失敗）。
- 強度：第一版只提供「低」（預設）與「中」。低＝去語氣詞／重複／明顯口誤；中＝可合併碎句、調整順序但仍不得新增事實。不做高強度「改寫成另一種文體」。
- 提示硬規則：只根據輸入句子整理；不得新增、推測或補完沒說出的內容；不能發明時間或說話者。
- 清稿可複製；可刪除後重跑。原文不可被這一步覆寫。

## 資料模型
- `transcript_cleanups`（或檔案）：`recording_id`、`intensity`、`payload_json`（`[{id, text}]`）、`source_revision`、`created_at`。同一強度只留最新一份。
- 原文 revision 改變時標過期，不自動重跑。

## API／成本／隱私
沿用既有雲端摘要／相容 endpoint 與金鑰，不新增服務。每次手動觸發大約送一份逐字稿的 token，**有成本**，不可宣稱免費。未開啟雲端或無金鑰時按鈕停用。不把內容寫進 log。

## 邊界情況
- 空稿、「目前無重點」無關：沒有逐字稿就停用。
- 超長錄音：可按句分塊；任一塊失敗則整次失敗（第一版）。
- 離線：不能新跑；已存清稿可離線閱讀與複製。
- 模型回傳多出的句子或缺少 id：整批丟棄。

## 驗收測試
1. 單元：id 對齊驗證；多餘／缺失 id 拒絕。
2. 單元：不覆寫原文；revision 過期標記。
3. 單元：確認對話取消則不發請求。
4. 手動：低強度稿仍能對回原句並跳轉（時間用**原文**的 `start_ms`，清稿不得自帶時間）。

## 依賴
需要已保存、可分段的逐字稿。跳轉用 #21 原文時間。

## 非目標
模仿指定作家風格、自動每次轉錄後清稿、用清稿覆寫逐字稿、會議重點自動改成書信、跨 App 系統聽寫鍵盤。
